Real. Working. Unreachable.

One Agent

One Address

A bundle-relative address. It resolves inside an Amplifier session and nowhere else.

“The expertise is fine. Its packaging is the problem.”

Beat Two · The Architectural Move

Two protocols, not one

Acquires Evidence

A backend with web access

A research service, or an agent with tools. It may bring new sources into a run — that is its entire job.

Reasons Over Evidence

An agent with no tools

It may only cite what the run already gathered. A synthesis citing a source the run never collected is rejected and repaired.

We considered collapsing both into one Agent abstraction with a can_search flag, and declined. They do not differ in shape — they differ in authority: what each is permitted to introduce into the caller's world. Reversibility runs in one direction only, and the type system makes the wrong direction unrepresentable.

Beat Two · The Architectural Move

Pointer, not copy

The installed skill used to carry the whole of --help with an install block spliced in, guarded by a test asserting that derivation. The test checked the wrong thing: it proved the file matched --help in this repository at build time — not what a caller's pinned install actually has.

# release 0.6.0 installed SKILL.md 155 lines → 69 lines --help (agent-facing) 142 lines, untouched # the 69-line file says four things: # what the tool is # how to install it # that --help is the real skill # how to tell whether your copy is current

A pointer cannot go stale, because it asserts nothing --help would. --help is printed by the binary the caller actually has — correct by construction, not by our diligence.

Beat Two · The Architectural Move

Attractor — assessed, declined

Buildable-with. We read the orchestrator's engine source directly and declined it, for three reasons.

Reason One

llm-direct is bare model calls, not a tool-using agent. Research needs web access, which means a spawned session — back inside the runtime we were trying to avoid.

Reason Two

Fan-out width is fixed at parse time from edges in the .dot text. Fact-check has N claims, N unknown until runtime.

Reason Three

Neither pipeline branches. A four-node linear graph is a for-loop; the engine means owning two failure domains instead of one.

Two things kept anyway: its checkpoint discipline (write after every node, carry a graph fingerprint, refuse loudly to resume a bad one) and its event vocabulary (node_start, node_complete, checkpoint, error).

“Adopt an orchestrator when the control flow is the hard part; when the control flow is a for-loop, the orchestrator is the hard part.”

Beat Three · How The Experience Evolved

Believed. Measured. Measured properly.

01 · BELIEVED

N=1, confound stated

A 2x gap on one run each. Unmeasured variance, said plainly rather than treated as a result.

02 · MEASURED PROPERLY

3 per arm, interleaved

Six live runs, on/off/on/off/on/off. Ranges don't overlap — 488–567s vs 281–335s. Real, on sharp questions only.

03 · BUILT THE MISSING POPULATION

Vague questions, blind pairwise

Three questions, one judge, one run per arm, judged twice with positions inverted. Skipping scope loses 6–6.

04 · AND THEN

The prose outran the measurement

Twice. Not a victory lap — the next two slides are where we were wrong.

Beat Three · How The Experience Evolved

The prose outran the measurement — twice

fix(hdm)

A rule we never measured

The skill said: pass the flag when a program composed the question, leave it off when a person did. That turns a property of the question into a property of its author. A person can ask a perfectly sharp question — the test task was exactly that. An agent obeyed the rule faithfully and left the saving on the table.

Direction, not magnitude

“Saves ~37%” was the wrong number

37% is what scope adds; skipping it saves ~27%. One measurement, two numbers, and every place we'd written it quoted the flattering one. Wall-clock had the same error: +69% with, −41% without.

Both times an agent trying to act on the text found it — never a human re-reading it. A ratio changes meaning with its denominator, and the sentence reads fine either way, which is precisely why it survives review.

“A better-presented document is obeyed more exactly. That is a multiplier, not an improvement.”

Beat Three · How The Experience Evolved

Nine of eleven sections carried no measurement

— and read with the same authority as the two that did. The exact failure our own tools exist to prevent, committed in the document arguing for preventing it. So every section now opens with its tier.

MEASURED

A before/after or A/B we actually ran, with the figures and their sample size attached.

OBSERVED

Something we read in source or watched happen. True, but not a measurement.

JUDGMENT

An argued call. The reasoning is shown; the other arm was not built.

PROPOSAL

A design we have not implemented or measured. An argument, nothing more.

Read a PROPOSAL as an invitation to disagree. Read MEASURED with its sample size attached — almost all of ours are N=1 per arm.

Beat Four · Expertise Escaping Amplifier

Four arms. One wrong answer — and it was ours.

The task: a sharp question, a tight budget, a nearly-full context. Correct call: --depth low --no-scope --no-inline. Four agent runs, one per arm — self-reported by each agent's own account of its steps; no raw transcripts.

The only wrong answer in four arms came from our own documentation, not from any host: the arm reading the newer, more confident-sounding skill obeyed a rule we had gotten backwards. The arm reading the older, scrappier docs noticed the two texts disagreed and judged the more precise one authoritative — and got it right.

Beat Four · Expertise Escaping Amplifier

A third harness, and what it can say that two cannot

Two hosts show a convention is not Amplifier-specific. Two cannot distinguish “works everywhere” from “works in the two places we happened to try.” Codex CLI 0.154.0 was the third arm, same task, same constraints.

HostStepsFinal command
Amplifier (corrected)7--depth low --no-scope --no-inline
Claude Code6--depth low --no-scope --no-inline
Codex CLI 0.154.05--depth low --no-scope --max-sources 3 --no-inline

Codex added --max-sources 3 and labelled it: “Three is a judgment call, not a documented optimum or guaranteed saving.” It quoted our own “NOT MODELLED” text back at us rather than guessing silently. Worth stating plainly: two hosts discovered the skill, three drove the tool — Claude Code found it unaided; Codex was pointed at .agents/skills/ in the prompt, so we cannot claim it would have found the skill on its own.

Beat Four · Expertise Escaping Amplifier

Two hosts, two different inventions, one real gap

Neither host was told how to wait when its own call limit is shorter than the interval it was handed. Both had to invent something. Neither invented the same thing.

Claude Code · 13 commands

9 bounded poll loops

Each loop: 9 iterations of 10 seconds, breaking early on a final state — sized to stay under its own 120-second command ceiling.

Codex · 45 commands

31 individual status polls

Reached for --detach unprompted and completed a 658.8-second run against the same 120-second ceiling — no command killed, no timeout raised.

The gap is real — 2 of 2 hosts improvised — and the workaround is host-specific. The spec should state the obligation (wait without blocking past your own limit) and must not prescribe the mechanism, because two capable hosts picked different ones and both were correct.

Beat Four · Expertise Escaping Amplifier

The discipline that traveled

A real run, real money, driven entirely from the installed skill in Claude Code: $0.05799, 15 sources, correct flags chosen by the agent. Unprompted, it reported which claims were thinly sourced:

“Only two sources were explicitly pinned to the claims… the join-semilattice framing had no source pinned to it in the gathered evidence.”

“The citation-integrity discipline survived into a foreign harness and reached the end user, rather than being smoothed into a confident summary by the host in between.”
